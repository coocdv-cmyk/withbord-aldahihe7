# ADR-008 — قرار تغليف rasm-pro (المرحلة 2)

> **الحالة:** مقبول كـ spike للمرحلة 2، وليس تغليفًا نهائيًا.  
> **التاريخ:** 20 أكتوبر 2026.  
> **النطاق:** قرار + إثبات قابل للتكرار. التنفيذ الكامل (مثبّت، توقيع، تحديث، اختبار VM) مؤجل إلى المرحلة 9.

---

## 1. السياق

الهدف النهائي تطبيق محلي بنقرة واحدة على Windows، بلا Python عند المستخدم، مع:

- مشاريع وفيديوهات طويلة (20–30 دقيقة) و3 فيديوهات أسبوعيًا.
- نماذج Qwen محلية لا تُحزم ولا تُنزّل تلقائيًا.
- ffmpeg وffprobe كأدوات sidecar واضحة، لا تنزيل خفي.
- بيانات المشروع قابلة للنسخ الاحتياطي والاستعادة، منفصلة عن كود البرنامج.
- عدم كسر مشاريع الإنتاج الحالية أثناء التطوير.

الخيارات المدروسة: PyInstaller one-folder، PyInstaller one-file، Nuitka، Embedded
Python، ومثبّت MSIX/Inno. القرار التفصيلي في القسم 2.

---

## 2. القرار

**PyInstaller one-folder + sidecars** هو الخيار المعتمد للمرحلة 2 والافتراضي
للمرحلة 9، مع بديل Embedded Python إذا فشل التحقق على جهاز نظيف.

الأسباب:

1. one-folder يبدأ أسرع من one-file ولا يعيد فك الحزمة عند كل تشغيل.
2. يمكن وضع `ffmpeg.exe`/`ffprobe.exe` في `runtime/` بجانب التنفيذي، فيبقى
   ترخيص ffmpeg ومساره صريحين.
3. يمكن فصل `projects/` و`cache/` و`config.json` عن `_internal/` (كود
   البايثون والأصول المقروءة فقط).
4. التحديث المستقبلي يمكن أن يستبدل `_internal/` دون لمس بيانات المشروع.
5. لا يحتاج المستخدم إلى Python أو pip أو صلاحيات مسؤول للتشغيل الأساسي.

one-file لم يُعتمد لأنه يبطئ الإقلاع، ويصعّب استبدال ffmpeg والنماذج، ويزيد
احتمال فقدان البيانات عند فشل فك الحزمة. Nuitka وEmbedded Python يبقيان
بدائل مراجعة في المرحلة 9، وليسا مسار التنفيذ الحالي.

## 3. بنية الحزمة والبيانات

```text
rasm\
  rasm.exe                 ← نقطة الدخول (CLI الآن، واجهة لاحقًا)
  _internal\               ← كود PyInstaller، Python، المكتبات، assets المقروءة
    assets\fonts\...
    engine\core\schema\...
    style_packs\paper_ink_v1.json   ← حزمة الأنماط المرفقة (للقراءة فقط)
  style_packs\             ← نسخة المستخدم القابلة للتعديل (تُنشأ عند التشغيل)
  runtime\                 ← اختياري: ffmpeg.exe + ffprobe.exe
  projects\                ← يُنشأ عند أول تشغيل
  cache\  logs\  library\  ← تُنشأ محليًا
  config.json              ← يُنشأ/يُنسخ يدويًا، لا يُحزم بأسرار
```

> **ملاحظة:** قياس النسخة (spike7) أكّد أن PyInstaller 6 يضع ملفات البيانات داخل
> `_internal`. لذلك تُحمَّل حزمة الأنماط من `_internal\style_packs` عبر
> `BUNDLE_STYLE_PACKS`، بينما يبقى مجلد `style_packs` بجانب `rasm.exe` للمستخدم
> (الأولوية له). هذا مُغطّى باختبار في `tests/test_packaging_paths.py`.

### جذر البيانات

`engine/core/paths.py` يحدد:

- `BUNDLE` = الأصول المقروءة فقط داخل الحزمة.
- `ROOT` = جذر البيانات القابل للكتابة:
  - `RASM_HOME` إن وُجد.
  - وإلا بجانب `rasm.exe` في النسخة المحزومة.
  - وإلا جذر `rasm-pro` في الكود المصدري.

هذا يسمح باختبار الحزمة على بيانات الإنتاج عبر `RASM_HOME` دون نسخها، ويمنع
كتابة المشاريع داخل `_internal` عند التوزيع النهائي.

### ffmpeg

لا يُضمَّن ffmpeg في spike. البحث بالترتيب:

1. `RASM_FFMPEG` (مسار الملف).
2. `RASM_FFMPEG_DIR` أو `runtime/` بجانب التنفيذي أو `_internal/runtime/`.
3. `RASM_HOME/runtime` و`RASM_HOME/../studio/runtime` للتطوير.
4. `PATH`.

هذا يمنع التنزيل الخفي ويمنع الافتراض الصامت بوجود أداة نظام. أي فشل يظهر
كرسالة صريحة، لا كسقوط إلى cloud أو أداة أخرى.

## 4. البناء القابل للتكرار

من داخل `rasm-pro`:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
# أداة بناء فقط، ليست اعتمادًا للمستخدم النهائي:
.venv\Scripts\python.exe -m pip install pyinstaller
.venv\Scripts\python.exe tools\build_portable.py
```

الناتج الافتراضي: `rasm-pro\build\portable\dist\rasm\rasm.exe`.

`tools/build_portable.py` يحزم:

- `rasm.py` و`engine` (مع schema).
- `assets` (الخطوط وأقلام الرسم) — 59.3 MiB في القياس.
- `config.example.json` و`style_packs/paper_ink_v1.json`.

ولا يحزم: `projects/`، `backups/`، `studio/models/`، `studio/runtime/`،
`config.json`، `library/manifest-icons.jsonl`، أو أي مفتاح/سر.

## 5. إثبات المرحلة 2

القياس على جهاز التطوير (Windows، Python 3.13.15، PyInstaller 6.22.3):

| البند | النتيجة |
|---|---|
| البناء | 49.8–77.5 ثانية (ثلاثة قياسات) |
| الحجم | 325,209,878 بايت ≈ 310.1 MiB |
| عدد الملفات | 371 |
| بدء `rasm.exe --help` | 10.2 ثانية (بارد) / 1.77 / 1.54 ثانية |
| `project validate ww1` | exit 0، 34 أصلًا، 3 رندرات، 4 غير محسوم |
| رندر 1 ثانية من الحزمة | 24 إطارًا، 1.000ث، h264، 1280×720، exit 0 |
| نظافة البيانات | لم تُنسخ مشاريع أو نماذج إلى الحزمة |

الأدلة الكاملة في `qa/stage2/stage2-evidence.json` وسجلات `qa/stage2/*.log`.
نُفّذ الاختبار من مجلد معزول على نفس الجهاز مع `RASM_HOME` يشير إلى بيانات
التطوير؛ **لم يتوفر VM نظيف**، لذلك قبول «بيئة نظيفة» يبقى شرطًا مؤجلًا
للمرحلة 9، وليس ادعاءً منجزًا.

### 5.1 اختبار التثبيت المعزول (spike8 + محرك المرحلة 3)

بعد إضافة بوابة الأصول (المرحلة 3) أُعيد البناء واختُبرت الحزمة في **تثبيت
نظيف** بلا `RASM_HOME` وبلا شجرة المصدر على `PATH`:

| الخطوة | النتيجة |
|---|---|
| `rasm.exe --help` | exit 0 · 14.82ث (بارد) |
| `rasm.exe approvals --help` | exit 0 · أوامر المرحلة 3 داخل الحزمة |
| `rasm.exe plan demo` | exit 0 · خطة مبنية من `scriptgraph.json` |
| `rasm.exe project init demo` | exit 0 · مانيفست + نسخة ترحيل |
| `rasm.exe approvals list demo` | exit 0 · 0 أصول |
| `rasm.exe render demo --preview --max-seconds 1` | exit 0 · 24 إطارًا · 1.000ث · h264 · 1280×720 |

- ffmpeg/ffprobe وُضعا في `<install>\runtime\` (التخطيط الموثّق) واكتُشفا تلقائيًا.
- مجلد البيانات أُنشئ **بجانب `rasm.exe`** (`cache`, `library`, `logs`,
  `projects`, `style_packs`) — لا شيء داخل `_internal`.
- **صفر** إشارة إلى شجرة المصدر في سجلات التشغيل.
- الدليل: `qa/packaging/isolated-install.json`.

> ما زال ينقص: نظام تشغيل/جهاز ثانٍ نظيف فعلًا. هذا الاختبار يعزل مجلد
> التثبيت، لا نظام التشغيل — لذلك يبقى بند VM نظيف مفتوحًا حتى المرحلة 9.

### بديل الاختبار النظيف (موثّق)

عند توفر VM أو جهاز ثانٍ بلا Python:

1. انسخ مجلد `rasm` كاملًا (بما فيه `runtime` إن استُخدم).
2. شغّل `rasm.exe --help`.
3. شغّل `rasm.exe project validate <id>` على مشروع اختباري.
4. شغّل رندرًا قصيرًا (1–10 ثوان) وتحقق من `ffprobe` أن الإطارات والمدة
   والمعدل مطابقة.
5. تأكد أن `RASM_HOME` أو مجلد البيانات أُنشئ خارج `_internal`.

## 6. الترخيص والامتثال

**مُنجز في 20 أكتوبر 2026** (التدقيق الكامل في `docs/10-LICENSE-AUDIT-AR.md`):

- كود المشروع: **MIT** — ملف `LICENSE` في جذر المستودع.
- `THIRD_PARTY_NOTICES.md`: كل ما يُوزَّع (الخطوط 38×OFL-1.1 + 1×Apache-2.0،
  الكود) وكل ما يُستخدم محليًا (Qwen Apache-2.0، ffmpeg، PyInstaller).
- ffmpeg: بنية GPLv3 (`--enable-gpl --enable-version3`، ونص GPL مرفق في
  `studio/runtime/FFMPEG-LICENSE.txt`) → **لا يُحزَّم**؛ يبقى sidecar خارجي.
- PyInstaller: استثناء الـ bootloader → المخرَج ليس عملًا GPL.
- `config.example.json` أصبح محمولًا (لا مسار مطلق للنموذج).

المتبقي قبل التوزيع العام:

- [ ] إن نُشر التطبيق **مع** ffmpeg: الالتزامات تخص ذلك الملف (GPLv3).
- [ ] مراجعة تراخيص مكتبة الأيقونات لو نُشرت المكتبة نفسها (غير مطلوب الآن).
