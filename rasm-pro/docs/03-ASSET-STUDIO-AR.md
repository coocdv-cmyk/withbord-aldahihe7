# 03 — استوديو الأصول الورقية والكولاج (Asset Studio)

> **الخلاصة:** نعم، يمكن تخصيص SD1.5 داخل المشروع، لكن **ليست الطريقة الذكية على هذا الجهاز الآن** أن نبدأ بتدريب LoRA. الجهاز CPU فقط (i5-1135G7، 4 أنوية، 16GB RAM)، وتدريب SD1.5 عليه قد يستغرق ساعات طويلة بجودة غير مضمونة. لذلك بنينا طبقة أقوى وأسرع: **توليد ورقي إجرائي (Procedural) + SD1.5 اختياري + عقل بايثون للاختيار والفحص والمعالجة**. النتيجة أصول بهوية المشروع، قابلة للتكرار، وتعمل حتى لو حُذف الموديل.

---

## 1. ما الذي بُني فعليًا؟

```text
rasm-pro/
  style_packs/paper_ink_v1.json       ← عقد الهوية: ألوان، أنواع، قيود، QA
  engine/assets/
    style.py                          ← تحميل الستايل والألوان
    procedural.py                     ← توليد الورق/الكولاج بدون موديل
    sd15_worker.py                    ← عامل SD1.5 في .venv-gen
    sd15.py                           ← جسر الكاش والعزل عن بيئة الرندر
    post.py                           ← توحيد الألوان، الحبيبات، منطقة النص، contact sheet
    qa.py                             ← فحص موضوعي (ألوان/تشبع/ازدحام/وجوه/شفافية)
    brain.py                          ← "مدير فني" قواعدي يختار النوع من وصف المشهد
    studio.py                         ← التنسيق، التكرار، الاختيار، الحفظ، السجل
  assets/generated/                   ← الأصول + manifest.json + contact sheets
```

**المحرك لا يعتمد على أي موديل.** الأصول تُحفظ PNG عادية، والخطة تشير إليها كأي صورة.

---

## 2. لماذا "إجرائي أولًا" وليس SD1.5 فقط؟

| النوع | الإجرائي | SD1.5 |
|---|---|---|
| ورق قديم/برشمان/كرافت | فوري، حتمي، دقة كاملة، بلا GPU | غالبًا أسوأ من الإجرائي للنسيج |
| ورق مسطر/شبكي/أزرق هندسي | دقيق ومضبوط | لا يضبط الخطوط بدقة |
| ورق ممزق/شريط لاصق/ملصق | شفافية وحواف مضبوطة | يحتاج تنقيحًا وقد يخطئ |
| بوستر/نباتي/خريطة/كولاج فني | بسيط ومحدود | مفيد للتنوع الفني |
| زمن التوليد | أقل من ثانية إلى ثوانٍ | ~3–4 دقائق/صورة على CPU |
| التكرار | نفس البذرة = نفس الصورة | نفس البذرة غالبًا، لكن أبطأ |
| التكلفة | صفر | كهرباء/وقت فقط |

الورق الذي نضع عليه الكلام **لا يحتاج** موديلًا؛ الإجرائي أدق وأسرع. SD1.5 نستخدمه للعناصر التي تحتاج "رسمًا" لا "نسيجًا".

---

## 3. هل ندرّب LoRA؟ الإجابة الصريحة

**نعم تقنيًا، لكن ليس الآن على هذا الجهاز.**

- SD1.5 LoRA عند 512×512، batch=1، رتبة 8–16، 800–1500 خطوة:
  - على RTX 3060 12GB: حوالي **30–60 دقيقة**.
  - على CPU الحالي: تقدير **10–30+ ساعة**، مع خطر عدم استقرار.
- يحتاج مجموعة بيانات: **30–80 صورة معتمدة** بنفس الهوية + وصف نصي لكل صورة.
- يحتاج `peft` + `datasets` + `accelerate`، وهم غير مثبتين حاليًا.
- التدريب الكامل (DreamBooth/Full fine-tune) مرفوض: يستهلك الذاكرة، ينسى القدرات العامة، ولا يضيف قيمة تُذكر لأصول ورقية.

**البديل العملي الآن:**

1. نولّد 30–50 أصلًا إجرائيًا/مختلطًا.
2. نعتمد الأفضل يدويًا (`assets approve`).
3. لاحقًا، عند توفر GPU، ندرّب LoRA على المعتمدين فقط.
4. الـLoRA يصبح اختياريًا داخل نفس الـStyle Pack، والـfallback الإجرائي يظل يعمل.

> لا نشترط GPU اليوم. الـPipeline جاهز، والتدريب مرحلة لاحقة عندما تتوفر البنية.

## 4. الأنواع المتاحة

`seamless_paper` — نسيج منخفض التباين للخلفيات المتكررة.

### كروت وقصاصات
`torn_paper` — ورقة ممزقة بحواف شفافة وظل.  
`paper_scrap` — قصاصة صغيرة للكولاج.  
`postcard` — بطاقة بريدية بحواف وختم دائري.  
`poster` — بوستر هندسي بدون نص، بمنطقة مركزية نظيفة.  
`photo_frame` — إطار صورة شفاف المركز.  
`sticker` — ملصق ورقي بحواف بيضاء.  
`label_tag` — بطاقة ورقية بثقب.

### طبقات فوقية
`tape_strip` — شريط لاصق شفاف.  
`ink_stain` — بقع حبر.  
`halftone` — شاشة نقاط.  
`fold_lines` — خطوط طي.  
`vignette_overlay` — تعتيم أطراف.

### SD1.5 اختياري
`vintage_poster` — بوستر عتيق (fallback: `poster`).  
`collage_element` — عنصر كولاج معزول (fallback: `paper_scrap`).  
`map_fragment` — جزء خريطة قديمة (fallback: `parchment`).  
`botanical_print` — مطبوعة نباتية (fallback: `paper_scrap`).

## 5. الأوامر

من داخل `rasm-pro`:

```powershell
# فحص البيئة والستايل وSD1.5
python rasm.py assets doctor

# أنواع الأصول
python rasm.py assets kinds

# ورق عتيق كخلفية 2560×1440، ثلاث نسخ
python rasm.py assets generate aged_paper --size 2560x1440 --count 3 --seed 42

# ورقة ممزقة ككارت
python rasm.py assets generate torn_paper --size 1600x1000 --count 3 --seed 10

# بوستر إجرائي بمنطقة نص نظيفة
python rasm.py assets generate poster --size 1600x1200 --count 2 --seed 16

# SD1.5 (اختياري، بطيء على CPU)
python rasm.py assets generate vintage_poster --size 1024x1024 --method sd15 --steps 20 --count 1

# قائمة الأصول
python rasm.py assets list --kind aged_paper

# اعتماد/رفض أصل
python rasm.py assets approve aged_paper_42_d00f1e --note "خلفية معتمدة"
python rasm.py assets reject  aged_paper_143_810f5a --note "تباين عالٍ"

# اقتراح نوع من وصف المشهد (عقل قواعدي)
python rasm.py assets brain "مشهد عن الحرب العالمية الأولى وأرشيف قديم" --purpose background
```

بديل مباشر بدون `rasm.py`:

```powershell
python -m engine.assets.studio generate aged_paper --size 2560x1440 --count 3
```

> **مهم:** `--out` افتراضيًا يحفظ في `assets/generated/paper_ink_v1/<kind>/`. لو أردت مجلدًا آخر استخدم `--out`.

## 6. العقل البرمجي: ماذا يفعل بالضبط؟

1. **اختيار النوع:** `brain.py` يقرأ وصف المشهد (حرب/تاريخ/علم/رسالة/نبات/كولاج/خبر) ويقترح النوع والبدائل.
2. **اختيار الطريقة:** `auto` يقرأ `method` من الستايل. لو SD1.5 غير متاح، يذهب للـfallback الإجرائي بدل ما يفشل.
3. **توليد مرشحين:** كل مرشح ببذرة مختلفة (`seed`, `seed+101`, ...).
4. **المعالجة اللونية:** تحويل تدريجي إلى لوحة الورق/الحبر، تقليل التشبع، حبيبات، فينييت.
5. **منطقة النص:** قياس التباين/الحواف في المستطيل الآمن، ثم **تنعيم انتقائي** (وليس مستطيلًا مرسومًا) لو كانت مزدحمة.
6. **الفحص:** مسافة اللوحة، التشبع، ازدحام منطقة النص، الوجوه، الدقة، تغطية الشفافية، pHash للتكرار.
7. **الاختيار:** الأعلى درجة فقط، وإلا يعيد ببذرة جديدة. لو فشل الجميع: fallback إجرائي أو خطأ واضح (أو `--allow-fail` للمراجعة).
8. **الحفظ:** PNG + JSON لكل أصل + `manifest.json` + `contact sheet` للمراجعة.
9. **الاعتماد:** قرار بشري مخزّن في `approved.json`، ولا يُستخدم الأصل في الإنتاج قبل الاعتماد.

هذا هو الفرق بين "سكربت صور" و"استوديو أصول": **عقد هوية + قياس + رفض + اعتماد + سجل**.

## 7. التكامل مع خطط rasm-pro

### أ) خلفية كاملة

```json
{
  "type": "background",
  "rect": [0, 0, 2560, 1440],
  "asset": "assets/generated/paper_ink_v1/aged_paper/aged_paper_42_d00f1e.png"
}
```

`background` (أو `texture`) يُرسم مرة واحدة في بداية المشهد، ثم النص فوقه. لا يمر بمسح/تتبع الصورة.

### ب) كارت ورقي بملمس مولّد

```json
{
  "type": "paper_card",
  "rect": [300, 700, 1200, 700],
  "texture": "assets/generated/paper_ink_v1/torn_paper/torn_paper_10_91013b.png",
  "style": "plain",
  "tape": true,
  "shadow": 0.35,
  "border": 10
}
```

`paper_card` يحتفظ بالظل والشريط اللاصق، لكنه يستبدل لون الورق بالملمس المولّد.

### ج) قصاصة/ملصق

حاليًا عنصر `image` يمر عبر `raster_to_strokes` (تحويل لخطوط)، لذلك **لا يُستخدم للشفافية**. للقصاصات استخدم `paper_card` أو أضفها لاحقًا كطبقة RGBA في الرندر. الورق الكامل والخلفيات آمنة.

## 8. إعدادات SD1.5

- البيئة: `D:\withbord inmation\.venv-gen` (torch CPU 2.14، diffusers 0.35.2).
- الموديل: `stable-diffusion-v1-5/stable-diffusion-v1-5` من كاش Hugging Face المحلي.
- لا يتحمّل أي شيء من الإنترنت وقت التوليد (`local_files_only=True`).
- الدقة: 512×512 داخليًا، ثم تكبير/قص إلى حجم الأصل.
- الخطوات الافتراضية: 20. على CPU ~3–4 دقائق/صورة.
- عدد توكنات CLIP: 77؛ الـprompt يُقصّ عمليًا عند ~65 كلمة، والـworker يسجل `truncated`.
- **لا يوجد safety checker** (محلي، والفحص لدينا موضوعي + مراجعة بشرية).
- الـworker معزول في subprocess؛ لو تعطّل، الرندر لا يتعطّل.

### ماذا نطلب من SD1.5؟

استخدمه لما يجيده: **عناصر كولاج، نباتي، خريطة، وخلفيات فنية بلا نص**. لا تستخدمه لورق مسطر أو شبكي؛ الإجرائي أدق.

**قرار Phase 3.2:** لا نستخدم SD1.5 كمسار افتراضي للبوستر الذي سيحمل نصًا. تجربة 20 خطوة أنتجت شكلًا مركزيًا مزدحمًا، وفشلت QA بسبب `text zone busy 0.33 > 0.20`؛ حتى بعد التنظيف بقي الازدحام. البوستر الإجرائي هو الافتراضي، وSD1.5 يبقى لعناصر الكولاج/النباتي/الخرائط ذات الخلفية النظيفة. عند فشل QA، شغّل `--allow-fail` لرؤية السبب وحفظ أفضل مرشح للمراجعة البشرية.

## 9. QA: ما الذي يُفحص؟

| المقياس | المعنى | العتبة الافتراضية |
|---|---|---|
| `palette_distance` | قرب الألوان من لوحة المشروع (Lab) | ≤ 46 |
| `saturation` | متوسط التشبع | ≤ 0.52 |
| `text_zone.busy` | ازدحام منطقة النص (حواف/تباين) | ≤ 0.20 |
| `faces` | عدد الوجوه (Haar) | 0 |
| `resolution` | الحد الأدنى | 768×512 للخلفيات، 256×256 للطبقات |
| `alpha_coverage` | تغطية الشفافية للقصاصات/الطبقات | ≥ 0.015 |
| `phash` | تكرار بصري | Hamming > 3 |
| `score` | مجموع موضوعي | ≥ 52 |

هذه ليست بديلًا عن العين. **الاعتماد البشري إلزامي** قبل استخدام الأصل في فيلم إنتاجي. الفحص لا يكتشف كل النصوص/الشعارات؛ لذلك برومبت "no text" + مراجعة بشرية.

## 10. الهوية والترخيص

- الأصول الإجرائية: ملك المشروع، مولّدة محليًا.
- أصول SD1.5: تخضع لترخيص **CreativeML OpenRAIL-M**؛ سجّلنا ذلك في metadata. لا نستخدمها في سياق محظور.
- لا نستخدم أي API مدفوع أو سحابي.
- كل أصل له `sha256` و`phash` و`prompt` و`seed` و`style` في JSON.

## 11. خارطة التخصيص (LoRA) عندما يتوفر GPU

1. اعتمد 30–80 أصلًا من `assets/generated/paper_ink_v1/`.
2. أنشئ `dataset/` فيه `image.png` + `caption.txt` لكل أصل.
3. ثبّت: `pip install peft datasets accelerate`.
4. درّب LoRA على SD1.5:
   - الدقة 512، rank 8–16، lr 1e-4، 800–1500 خطوة.
   - على RTX 3060: 30–60 دقيقة.
5. ضع ملف الـLoRA في `models/loras/paper_ink_v1.safetensors` وحدّث `style_packs/paper_ink_v1.json` بحقل `lora`.
6. أضف اختبار انحدار: نفس البذور/البرومبتات، وقارن `phash` واللوحة.
7. **لا تحذف** الـfallback الإجرائي. الموديل يظل اختياريًا.

> لن نبدأ التدريب على CPU. النتيجة على الأرجح ستكون أبطأ وأسوأ من الإجرائي الحالي.

## 12. حدود معروفة

- SD1.5 على CPU بطيء (3–4 دقائق/صورة). لا تستخدم `--count 4 --method sd15` إلا إذا كنت مستعدًا للانتظار.
- SD1.5 512px، لذلك التفاصيل الدقيقة محدودة بعد التكبير.
- لا يوجد VLM محلي للحكم على الجماليات؛ الفحص موضوعي + مراجعة بشرية.
- كشف الوجوه Haar ليس مثاليًا؛ قد يفوّت وجوهًا صغيرة/جانبية.
- لا OCR؛ لا يمكن الجزم بعدم وجود نص داخل صورة SD1.5.
- `seamless` تحسين بسيط (roll+blend)، وليس ضمانًا رياضيًا لعدم وجود خطوط تكرار.
- "الاعتماد" حالة في JSON، وليس قفلًا تقنيًا؛ الـPipeline يحترمه، لكن يمكن تجاوزه يدويًا.

## 13. ماذا بعد؟

- إضافة المزيد من أنواع الأصول حسب احتياج المشاريع الفعلية (خرائط، طوابع، بطاقات ملفات).
- ربط `assets brain` بمولّد الخطة تلقائيًا لاقتراح خلفية لكل مشهد.
- إضافة اختبارات انحدار للـAsset Studio (نفس البذرة → نفس `phash`).
- عند توفر GPU: LoRA + مقارنة A/B مع الإجرائي.
- إضافة دعم RGBA للقصاصات داخل الرندر (طبقة بدل تتبع الخطوط).
