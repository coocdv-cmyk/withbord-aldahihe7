# حزمة الإنجليزية: LTR، الأوزان، والتحقق

> **الهدف:** أن ينتج راسم الفيديو الإنجليزي بنفس جودة الأسلوب العربي، لا كنسخة مشوّهة. العربية تبقى RTL، والإنجليزية LTR، والمختلط يتبع أول حرف قوي في السطر.

## 1. ما كان مكسورًا

`engine/strokes/text_paths.py` كان يرصف **الكلمات** دائمًا من اليمين إلى اليسار، ثم يعيد تطبيع الإحداثيات. النتيجة:

- ترتيب كلمات إنجليزية مقلوب، أو محاذاة يمينية غير مقصودة.
- المسافات بين الكلمات في السطر العربي كانت تُحسب في الموضع الخطأ.
- السطر المختلط («Hello العربية world») كان يُعامل كأنه عربي بالكامل.
- `find_font("inter")` كان يختار `Inter-Italic` لأن الفرز يفضّل الشرطة على القوس.

## 2. الإصلاح

### 2.1 اتجاه السطر وأول حرف قوي

- `base_rtl` يُحدَّد من **أول حرف قوي** (عربي أو لاتيني) في السطر.
- إذا كان `rtl` صريحًا في العنصر، يحترمه المحرك.
- الكلمة نفسها قد تكون باتجاه معاكس (عربية داخل إنجليزية أو العكس)؛ تُوضع كوحدة واحدة وتُشكَّل داخليًا.
- المسافات تُحسب قبل الكلمة في الاتجاه الصحيح، ثم يتقدم المؤشر يمينًا (RTL) أو يسارًا (LTR).

### 2.2 أوزان الخط المتغيّرة

- `text_to_strokes(..., weight=650)` يفعّل محور `wght` في خط Inter المتغيّر.
- الخط يُنسخ إلى نسخة ثابتة (`fontTools.varLib.instancer`) قبل رسم الحروف، وليس مجرد تغيير HarfBuzz.
- الكاش يتضمن الوزن؛ لا تعود مسارات قديمة بعد تغيير `weight`.
- `TEXT_PIPELINE_V` رُفع إلى `6` لإبطال كاش النصوص القديم.

### 2.3 بناء الخطة الإنجليزية

عندما يكون `lang` في تحليل السكريبت إنجليزيًا، `engine/stages/plan.py` يختار تلقائيًا:

| العنصر | الخط | الوزن | ملاحظة |
|---|---|---|---|
| العنوان | Inter | 650 | LTR، `rtl: false` |
| العنوان الفرعي | Inter | 500 | LTR |
| التسمية | Inter | 500 | LTR |
| التعليق | Inter | 500 | LTR |
| العنوان بلا صورة | Inter | 600 | LTR |

الخطة العربية تحتفظ بـ`arefruqaa`/`cairo` و`rtl: true`، فلا تتأثر.

## 3. مثال خطة إنجليزية

```json
{
  "lang": "en",
  "canvas": [2560, 1440],
  "fps": 30,
  "scenes": [
    {
      "id": 1,
      "duration": 5.0,
      "elements": [
        {
          "type": "text",
          "text": "The First World War",
          "font": "inter",
          "size": 220,
          "weight": 650,
          "rect": [220, 280, 2120, 700],
          "mode": "skeleton",
          "rtl": false,
          "color": "#211E1A",
          "gap": 0.25
        },
        {
          "type": "underline",
          "rect": [240, 780, 1200, 80],
          "double": true,
          "color": "#8C2F1F",
          "brush": 6.0,
          "offset": 14
        }
      ]
    }
  ]
}
```

- ضع `rtl: false` صراحةً في كل عنصر إنجليزي؛ هذا يمنع أي التباس في الخطط المولّدة يدويًا.
- `weight` اختياري، لكنه مهم للعناوين: 650 للعنوان، 500 للنص، 550–600 للأرقام.
- لا تستخدم خطًا عربيًا لنص لاتيني طويل؛ Inter/Cairo يدعمان اللاتينية، لكن Inter هو المسار الإنجليزي المقصود.

## 4. التحقق والرندر

```powershell
# فحص خطة قبل الرندر
python rasm.py validate projects/myproject/storyboard/plan.json

# فحص صارم: أي تحذير = فشل
python rasm.py validate projects/myproject/storyboard/plan.json --strict

# الرندر (يفحص الخطة تلقائيًا)
python rasm.py render myproject --plan plan.json

# للملفات القديمة فقط
python rasm.py render myproject --plan plan.json --skip-validate
```

`validate` يفحص:

- أنواع العناصر، `rect` موجب، المدد، `fps`، معرفات المشاهد المكررة.
- وجود الأصول (`image`/`svg`/`texture`/`background`/`texture` في `paper_card`).
- وجود الخط عبر `find_font`، وصحة `mode` و`weight`.
- تحذيرات: خلفية ليست أول عنصر، عنصر خارج اللوحة، `rtl: true` على نص إنجليزي.

## 5. الاختبارات

```powershell
python -m pytest tests/test_text_ltr.py tests/test_plan_english.py tests/test_plan_validate.py -q
```

- `test_text_ltr.py`: ترتيب الكلمات الإنجليزية، العربية RTL، السطر المختلط، واختيار Inter غير المائل.
- `test_plan_english.py`: خطة إنجليزية بأوزان وLTR، وخطة عربية سليمة.
- `test_plan_validate.py`: أخطاء وتحذيرات الخطة والأصول.

## 6. حدود

- الكشف التلقائي يعتمد على أول حرف قوي، وليس UAX#9 كاملًا. الحالات الشاذة (أرقام فقط، رموز فقط، اختصارات لاتينية داخل جملة عربية) تُحلّ بـ`rtl` صريح.
- Inter متغيّر؛ الخطوط الثابتة تقبل `weight` لكنه لا يغيّرها. استخدم ملفًا ثابتًا مناسبًا أو خطًا متغيّرًا.
- لا يوجد OCR أو VLM محلي؛ التحقق البصري النهائي بشري.
- الفحص لا يثبت جمالية التصميم، بل يمنع الأخطاء البنيوية والانحدارات المعروفة.
