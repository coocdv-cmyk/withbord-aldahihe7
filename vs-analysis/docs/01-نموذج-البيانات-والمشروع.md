## 0. خريطة طبقات النموذج

قبل الدخول في التفاصيل، هذه هي الطبقات التي يتكوّن منها «مشروع» VideoScribe في هذا الإصدار:

| الطبقة | الملف الرئيس | الدور |
|---|---|---|
| الأنواع (TypeScript) | `types.ts` (1901 سطرًا) | مصدر الحقيقة لكل الأشكال (`ScribeModelProps`, `ScribeScene`, `ScribeCameraElement`, `ScribeObject`, …) |
| نموذج المشروع | `models/ScribeModel.ts` | الكائن الجذري + الترحيلات + `fromObject` |
| نموذج العنصر | `models/ScribeElementModel.ts` والقواعد المشتقّة | العنصر العام + `Image` / `Shape` / `Text` |
| نموذج طبقة الصوت | `models/ScribeAudioLayerModel.ts` | مجموعة `audioClipIds` |
| طبقة Raw | `shared/lib/LocalDatabase/index.ts` | IndexedDB: كاش الأصول وكاش المسارات والـ SVG |
| طبقة النقل | `shared/helpers/app-services/AppServices/projects.js` | REST مع `project-data` |
| طبقة الحفظ التلقائي | `sagas/autoSaveSaga/*` | طابور + polling كل ثانيتين |
| ترحيل المشاريع القديمة | `sagas/legacyProjectMigration/*` | فك `.scribe` (ZIP+XML) وتحويله للموديل الحديث |

المفتاح لفهم المشروع كله: **المشروع ليس ملفًا محليًا**، بل مستند JSON يسكن على السحابة، ويُشتق منه `ScribeModel` في الذاكرة، بينما تبقى الصور والأصوات والخطوط أصولًا مستقلة (`assetId`) تسكن خزائن السحابة وكاشات محلية.

لاحظ ثلاثة قرارات تصميمية مهمة:

1. **العناصر مسطّحة والمشاهد مراجع**: `elements` مصفوفة واحدة، و`scenes[i].elementIds` إشارات. لذلك حذف مشهد لا يحذف عناصره تلقائيًا، وهذا مكمن الأخطاء المعروف في هذا النمط من الموديلات (يظهر أثره في `cleanupUnusedAudioLayersAndIds` ومساعدات التنظيف في `sagas/sagaHelpers/`).
2. **العنصر الأول في كل مشهد كاميرا**: هذا غير مُعبَّر عنه في الأنواع، بل مفروض إجرائيًا في `ScribeModel.ts:206-211` (سنتوسّع في القسم 3).
3. **النسخة مخزّنة على الكائن**: `lastSavedVersion` يُملأ من `scribeObject.version` عند البناء (`ScribeModel.ts:334`)، أي أن كل مشروع يعرف نسخة الصيغة التي وُلد بها.

### 1.4 `fromObject` و`ScribeObject` و`ProjectModel`

عند التحميل من السحابة يصل غلاف هو `ScribeObject` (`types.ts:1385-1394`):

```ts
// types.ts:1385-1394
export interface ScribeObject {
  projectModel: ProjectModel;
  projectDataId: number;
  createdDate: string;
  modifiedDate?: string;
  version?: string | number;
  viewOnly?: boolean;
  publicSharingId?: string;
  title: string;
}
```

و`ProjectModel` هو `ScribeModelProps` + عناصر اختيارية (`types.ts:1381-1383`):

```ts
export type ProjectModel = ScribeModelProps & {
  elements?: Array<VSElements>;
};
```

أي أن **صيغة الـ API تحمل نسختين من العناصر في الوثيقة نفسها**: `projectModel.elements` المسطّح (يُخزَّن فعليًا) و`projectModel.scenes[].elementIds` (الفهرسة). و`ScribeModelProps` (`types.ts:345-364`) كاملًا:

`id?, title, settings?, canvasSize?, thumbnailImage?, createdOn?, updatedOn?, cursor?, source?, scenes?, audioClips?, audio?, audioLayers?, rawElements?, modifiedDate?, publicSharingId?, pinAllCameras?, projectAudioLayerIds?`

نلاحظ حقولًا «واردة فقط للتوافق الخلفي»: `audio?` (قبل الطبقات)، `rawElements?` (تسمية قديمة للعناصر)، `modifiedDate?` (نصّي)، و`cursor?` على مستوى المشروع. هذه بقايا تاريخية تُثبت أن الصيغة تطوّرت على مراحل دون كسر مشاريع المستخدمين — وهذا في جوهره نظام إصدارات ضمني عن طريق الحقول لا رقم إصدار صريح.

و`fromObject` (`ScribeModel.ts:294-334`) هو نقطة الدخول الموحّدة:

- يبني الموديل من `ScribeObject` مع دمج `otherScribeModelConfig`
- يقرأ `contents.audioLayers` وغيرها
- وأخيرًا — وهذا سطر مفتاحي — `model.lastSavedVersion = scribeObject.version` (`ScribeModel.ts:334`)

معنى ذلك أن دورة الحياة كاملة: **GET → ScribeObject → ScribeModel.fromObject → Redux → تعديلات → sanitize → PUT`.

## 2. العنصر: الأنواع والتوقيت والأنيميشن

### 2.1 الخصائص الأساسية المشتركة

كل العناصر (عدا الكاميرا التي تنفصل بأنواعها) ترث الخصائص في `types.ts:75-112`. الجدول التالي يشرح مجموعاتها:

| المجموعة | الحقول | الاستشهاد |
|---|---|---|
| الهوية | `id: string`, `type: ElementType` | `types.ts:76-77` |
| الأبعاد والأوضاع | `width, height, x, y, scaleX, scaleY, angle` | `types.ts:78-84` |
| نقاط الأصل | `originX, originY: string` (عمليًا `left`/`top` دائمًا حسب تعليق `ScribeElementModel.ts:74-80`) | `types.ts:85-86` |
| الانعكاس والقفل | `flipX, flipY, locked, unlockedRatio, hidden, outOfCamera` | `types.ts:87-92` |
| التوقيت | `pauseTime?`, `customPauseTime?` (مهجور)، `animationTime?`, `emphasisAnimationTime?`, `exitAnimationTime?`, `emphasisAnimationLoops?` | `types.ts:94-100` |
| الأنيميشن | `cursorId?`, `entranceTween?`, `exitTween?`, `emphasisTween?`, `entranceAnimation?`, `emphasisAnimation?`, `exitAnimation?` | `types.ts:101-109` |
| تشفير | `isPremium?` | `types.ts:111` |

دلالات التوقيت كما وثّقها المطورون في `ScribeElementModel.ts`:

- `pauseTime` — زمن الانتظار بعد اكتمال العنصر. وهو **إعادة تسمية لـ`customPauseTime`**، ويحتفظ الكود بالتوافق: `this.pauseTime = typeof data.pauseTime === 'undefined' ? data.customPauseTime : data.pauseTime` (`ScribeElementModel.ts:218-220`).
- `animationTime` — زمن أنيميشن الدخول، وإن غاب يُستخدم الافتراضي (`ScribeElementModel.ts:137-140`).
- `emphasisAnimationTime` / `exitAnimationTime` — بلا افتراضي على مستوى العنصر (يُقرأ لاحقًا من إعدادات المشهد/المشروع).
- `emphasisAnimationLoops` — عدد تكرارات أنيميشن التأكيد (`ScribeElementModel.ts:155-157`).

### 2.2 الأنواع الأربعة

**`ElementType`** محدود بأربع قيم فقط: `'Text' | 'Shape' | 'Image' | 'Camera'` (`types.ts:366`)، والاتحاد الكامل `VSElementModel` هو `ScribeImageElementModel | ScribeShapeElementModel | ScribeTextElementModel | ScribeCameraElement` (`types.ts:64-68`).

| النوع | الحقول الخاصة | الاستشهاد |
|---|---|---|
| `Image` | `useContentSvgViewbox?`, `viewboxAttributes?` ({contents, original})، `image?: ImageDetails` {assetId, provider, contentType, recolor, filename}، `recolorAvailable?`, `containsEmbeddedImage?`، وحقول مؤقتة بالبادئة `_`: `_imageUrl`, `_imageLoaded`, `_imageLoading`, `_recolorDefaults` | `types.ts:114-125`, `types.ts:441-447` |
| `Shape` | `shapeType` (`square/triangle/circle/ellipse`), `fill`, `backgroundType`, `backgroundColorFrom/To`, `backgroundGradientType`, `radius?`, `rx?`, `ry?` + حقول بريطانية مهجورة `backgroundColourFrom/To` | `types.ts:127-144`, `types.ts:472` |
| `Text` | `font?: FontAttributes` {label, value, assetId, custom}، `text?`, `align?`, `fill?`, `color?`, `fontSize?`, `fontWeight?`, `fontStyle?`, `styles?` (ديكشنري صف/عمود للتلوين الجزئي)، `charBounds?`, `lineWidths?`, `lineHeight?` | `types.ts:158-173`, `types.ts:459-464` |
| `Camera` | `x, y, scale, animationTime, pauseTime, locked, cameraPinned, easingType?` | `types.ts:1449-1460` |

نقطتان تقنيتان جديرتان بالتوقّف:

1. **`charBounds`**: كل عنصر نص يخزّن حدود كل حرف (`TextElementCharBounds = {left,width,kernedWidth?,height?,deltaY?}[][]`, `types.ts:150-156`). هذا ما يمكّن رسم النص حرفًا حرفًا (hand-draw للخطوط) ومزامنة الإبراز الصوتي. إنه أيضًا سبب ارتباط النص بالخط: تغيير الخط يبطل `charBounds`.
2. **الحقول الفورية (`_imageUrl` …)**: ليست جزءًا من العقد، وتُمسح قبل أي إرسال عبر `sanitizeScribeForTransport` (سنراها في القسم 5).

### 2.3 الحافظة والاستنساخ (Clipboard)

نموذج الحافظة جزء من عقد المشروع لأنه يُستخدَم للنسخ بين المشاريع أيضًا (`types.ts:474-504`):

- `ElementClipboardPayload`: `{ type: 'element', metadata: { sceneId, wasCut }, data: Array<Partial<VSElementModel>> }` — أي أن نسخ عنصر يحمل «مشهد المصدر» و«هل كان قصًّا» ليتمكّن اللصق من إزالة الأصل عند `wasCut`.
- `SceneClipboardPayload`: `{ type: 'scene', metadata: { elements: Array<ElementClone>, canvasSize, audioClips?, audioLayers? }, data: Array<SceneClone> }` — أي أن نسخ مشهد يحمل **العناصر والطبقات الصوتية والمقاطع معه**، لأن المشاهد وحدها بلا محتواها لا معنى لها.

و`ElementClone` / `SceneClone` هما نسخ بلا `id` (أو بـ`tempId` بديل) حتى تُسنَد معرّفات جديدة عند اللصق (`types.ts:496-504`). عمليات التنفيذ في `sagas/sagaHelpers/`: `createSceneClipboardPayload` للنسخ، `pasteScenesIntoScribe` للصق، و`duplicateScenesIntoScribe` للاستنساخ داخل المشروع نفسه، و`deleteScenesFromScribe` للحذف. هذا يفصل «نية العملية» (clipboard) عن «تنفيذها» (saga)، وهو نمط يجب نسخه.

### 2.4 تمثيل الأنيميشن

الأنيميشن يُمثَّل بصيغتين متوازيتين:

```ts
// types.ts:383-404
export interface TweenAnimation {
  id: AllAnimationTypeKeys;
  tweens?: Array<Tween>;
  tweens_in?: Array<Tween>;
  tweens_out?: Array<Tween>;
}

export interface AnimationConfiguration {
  id: AllAnimationTypeKeys;
  config?: AnimationConfigurationOptions;
}
```

- `TweenAnimation` = **القيم الفعلية** للمفاتيح (`alpha, position, ease, scaleX, rotation, x, y, direction, percentage_of_total…` — `types.ts:368-381`) وتُخزَّن في `entranceTween/emphasisTween/exitTween`.
- `AnimationConfiguration` = **وصف مختصر** (المعرّف + إعدادات مثل `cursorId` و`drawType`) ويُخزَّن في `entranceAnimation/...`.

مجموعات المفاتيح (`types.ts:408-433`):

| المرحلة | المفاتيح المسموحة |
|---|---|
| دخول | `none, draw, pen-draw, hand-draw, fade-in, move-in, bounce-in, drag-in` |
| تأكيد | `none, bounce-loop, spin-loop, pulse-loop, shake-loop` |
| خروج | `none, fade-out, move-out, slingshot, disappear, exit-erase` |

وتُعرَّف مفاتيح المستندات النصية في `config/consts.ts:163-174` (`entrance`, `emphasis`, `exit` + `entranceTween`, `emphasisTween`, `exitTween` + `entranceAnimation`, …). والتعليق في `consts.ts:185` يكشف أن بعض أنيميشنات الدخول "تُخزَّن كـTween في الموديل" (`ENTRANCE_ANIMATIONS_THAT_ARE_STORED_AS_TWEEN_IN_MODEL`) أي أن جزءًا من الحقيقة محفوظ في الـ tween وجزءًا في الـ config — وهذا ازدواجية يجب أن يتجنبها أي إعادة تنفيذ.

### 2.5 محرّك التوقيت: الحقيقة الكاملة

ترتيب تشغيل العناصر = ترتيب `elementIds` داخل المشهد (لا حقول `startTime` على العنصر؛ فقط الكاميرا والصوت يملكان مفهوم البداية). الحسابات في `playback/helpers/timings.ts`:

- **الدخول**: `getElementEntranceAnimationTimeMs` — وإذا كانت الكاميرا **أول عنصر** في المشهد فزمنها 0 (`timings.ts:8-18`).
- **الخروج**: يُعاد 0 إذا كان العنصر كاميرا (`timings.ts:20-24`)، وإلا فيُقرأ الزمن **فقط** إن كان للعنصر tween/تكوين خروج (`timings.ts:25-28`).
- **التأكيد**: 0 للكاميرا، وإلا `emphasisAnimationTime` (`timings.ts:33-37`).
- **الإجمالي**: الدخول + التأكيد + الخروج + الوقفة (`timings.ts:77-84`).

وسلسلة fallback للتوقيت تُقرأ هكذا (مقتطف حرفي):

```ts
// playback/helpers/timings.ts:106-124
  if (element.type === 'Camera') {
    const cameraElement = element as ScribeCameraElement;
    if (
      cameraElement &&
      (property === 'animationTime' || property === 'pauseTime') &&
      cameraElement.hasOwnProperty(property)
    )
      return cameraElement[property];
  } else {
    if (element.hasOwnProperty(property)) {
      const elementProperty = element[property];
      if (elementProperty !== undefined) {
        return elementProperty;
      }
    }
  }
  if (scene && scene.settings && scene.settings.hasOwnProperty(property)) return scene.settings[property];
  if (scribe && scribe.settings && scribe.settings.hasOwnProperty(property)) return scribe.settings[property];
  return 0;
```

أي: **العنصر ← إعدادات المشهد ← إعدادات المشروع ← صفر**. هذا يعني أن تغيير إعداد المشروع يغيّر زمن كل عنصر لم يُثبَّت زمنه صراحة — قرار تصميمي يجعل «الحفظ الجزئي» للتوقيت مستحيلًا دون تسطيح القيم.

## 3. المشاهد والانتقالات والكاميرات

### 3.1 المشهد

```ts
// types.ts:285-292
export interface ScribeScene {
  id: string;
  active: boolean;
  elementIds: Array<string>;
  audioLayerIds?: Array<string>;
  settings: ScribeSettings;
  thumbnailImage?: string;
}
```

- `active` = المشهد المُعروض حاليًا في المحرر.
- `audioLayerIds?` = يقود حساب طول المشهد الصوتي (القسم 4).
- `settings` كاملة لكل مشهد (يمكن أن يختلف الانتقال وزمن الأنيميشن من مشهد لآخر).
- القيود العددية: `MAX_NUMBER_OF_SCENES = 25` و`MAX_NUMBER_OF_ELEMENTS = 150` (`config/defaults.ts:203-204`).

### 3.2 الانتقالات

المفاتيح في `config/consts.ts:196-212`:

| المفتاح | القيمة | ملاحظة |
|---|---|---|
| `none` | `'none'` | بلا انتقال |
| `slide` | `'slide'` | مع اتجاه |
| `bounce` | `'bounce'` | من `SCENE_TRANSITIONS_WITH_DIRECTION` |
| `fade` | `'fade'` | — |

وإعداد الانتقال `SceneTransitionConfig` (`types.ts:217-222`) يحمل `rotate?`, `times?`, `direction?`, `cursorId?`. الزمن الافتراضي للانتقال `0` (`ScribeModel.ts:46`).

يُحسب طول المشهد في `getSceneStartTimeAndLength` (`timings.ts:162-199`): مجموع أوقات العناصر، وإن وُجد صوت أطول من مجموع العناصر يُمدَّد المشهد (`getSceneAudioLength` + المقارنة، `timings.ts:184-199`). ويُزاح بدء مشهد بزمن الانتقال: `sceneStartTime = ... + sceneTransitionTime * 1000` (`timings.ts:149-151`). أي أن **زمن الانتقال يُضاف فوق زمن المشهد السابق**، وهي نقطة يخطئ فيها كثير من المقلّدين فتنحرف كل الأزمنة التراكمية.

### 3.3 عمليات المشاهد ومرافقاتها في الكود

حول كل عملية على المشاهد توجد مساعدات مخصّصة في `sagas/sagaHelpers/`، وهي تمثل «طبقة قواعد العمل» فوق الموديل:

| العملية | المساعد | ما يفعله |
|---|---|---|
| إنشاء مشهد | `createNewScene.ts` | يبني مشهدًا جديدًا بمعرّف جديد، ينسخ إعدادات المشروع إليه، ويضيف كاميرا افتتاحية كأول عنصر |
| نسخ مشاهد داخل المشروع | `duplicateScenesIntoScribe.ts` | ينسخ المشاهد ومحتواها بمعرّفات جديدة داخل المشروع نفسه |
| لصق مشاهد | `pasteScenesIntoScribe.ts` | يلصق `SceneClipboardPayload` مع إعادة بناء العناصر والأصوات |
| حذف مشاهد | `deleteScenesFromScribe.ts` | يحذف المشاهد مع تنظيف العناصر والطبقات التي لم تعد مستخدَمة |
| إعادة ترتيب العناصر زمنيًا | `rearrangeElementsOnTimeline.ts` | يعيد ترتيب `elementIds` وفق تعديلات المستخدم في الجدول الزمني |
| تحديث عناصر مشهد | `updateElementsInScene.ts` | تحديث مجمّع لعناصر داخل مشهد واحد |
| قصّ العرض حسب تغطية الكاميرا | `stripProjectOfElementsNotInSegmentCameraViews.ts` | يزيل العناصر غير الظاهرة في مقاطع الكاميرا المطلوبة (تحسين عرض/تصدير) |

الفكرة القابلة للنقل: **كل عملية نطاق (domain operation) لها ملف مستقل**، و`ScribeModel` نفسه لا يعرف سوى بنيته الداخلية وترحيلاته. هذا يحمي الموديل من النمو الزائد ويعطي المنافس خريطة واضحة لما يجب أن يبنيه من وحدات.

### 3.4 الكاميرا

```ts
// types.ts:1449-1460
export interface ScribeCameraElement {
  id: string;
  x: number;
  y: number;
  type: 'Camera';
  scale: number;
  animationTime: number;

```

قواعد الكاميرا المرصودة:

1. **واحدة على الأقل لكل مشهد، وأول عنصر فيه**: في `ScribeModel.ts:206-211` يُبحث عن العنصر الأول في المشهد، وإن لم تكن كاميرا (`type !== 'Camera'`) تُنشأ كاميرا وتُدرج في المقدمة. الكاميرا الافتتاحية زمن أنيميشن الدخول الخاص بها = 0 (لا حركة)، وأول `animationTime` افتراضيًا 0 عند إنشائها (`sagas/cameraSagas/addCamera.ts` + `getNewCamera`).
2. **التثبيت العام مفعَّل افتراضيًا**: `PIN_ALL_CAMERA_BY_DEFAULT = true` (`config/config.ts:62`)، ويُقرأ إلى `pinAllCameras` على المشروع (`ScribeModel.ts:68`).
3. **حركة الكاميرا تحسب تغطيتها من العناصر**: عبر `updateCameraCoverage` المستدعاة من الـ reducer عند كل `UPDATE_SCRIBE` على المشهد النشط (`reducers/scribesReducer.ts:220-221`)، بحيث تبقى الكاميرا متمركزة على العناصر المحددة.
4. **`outOfCamera`**: علم على العنصر (`types.ts:92`) يميّز العناصر الخارجة عن نطاق الكاميرا الحالية، وتُستخدم في `stripProjectOfElementsNotInSegmentCameraViews` عند العرض المُجزّأ.
5. **التخفيف (easing)**: ثلاثة أوضاع (none / ease-out / linear) مضبوطة عبر `easingType` (`types.ts:1459`).

## 4. الصوت: الطبقات و wordforms

### 4.1 نموذج المقطع الصوتي

```ts
// types.ts:294-313
export type AudioClipData = {
  assetId: number;
  type: AudioType | AdvancedAudioType;
  source: AudioSource;
  volume: number;
  duration?: number;
  instanceDuration?: number;
  fadeOutDurationSeconds: number;
  filename: string;
  /**  @deprecated migrate to all lowercase property*/
  fileName?: string;
  startTime?: number;
  startOffset?: number;
  id?: string;
};
export type AudioClip = AudioClipData & { id: string };
```

دلالة الحقول: `duration` = الطول الأصلي للملف، `instanceDuration` = الطول المستخدَم في المشروع (اقتصاص/تقطيع)، `startTime` = موضع البدء داخل المشهد، `startOffset` = من أين يبدأ التشغيل داخل الملف، `volume` + `fadeOutDurationSeconds` = المزج. الدور `AudioRole = 'voiceover' | 'music'` (`types.ts:315`)، وبحد أقصى **طبقتين في المشروع** (`MAX_AUDIO_TRACKS_IN_PROJECT = 2`, `config/config.ts:61`)، وحد التسجيل 20 دقيقة (`config/config.ts:21`).

### 4.2 الطبقات والتنظيم

`ScribeAudioLayerModelProps = { id, audioClipIds[] }` (`types.ts:340-343`). والطبقات على مستويين:

- **على المشهد**: `scene.audioLayerIds` — تعليق `timings.ts:41-43`.
- **على المشروع**: `scribe.projectAudioLayerIds` (`ScribeModel.ts:69`) — للموسيقى المستمرة عبر المشاهد.

الترحيلات المهمة: كائن `audio` المفرد القديم → `audioClips[]` (`ScribeModel.ts:80`)، وكل مقطع بلا طبقة تنشأ له طبقة تلقائيًا (`ScribeModel.ts:265-288`). ويوجد مساعد `cleanupUnusedAudioLayersAndIds` في `sagas/sagaHelpers/` لتنظيف الطبقات اليتيمة، و`updateAudioLayers` لإعادة الربط.

طول المشهد الصوتي = **آخر لحظة ينتهي فيها مقطع**: `startTime + instanceDuration` كحد أقصى (`timings.ts:58-67`). هذا يعني أن سلوك «التعليق الصوتي الطويل يمطّ المشهد» مُرمَّز رقميًا لا دلاليًا.

### 4.3 wordforms: مزامنة النص المنطوق

نظام wordforms يربط كلمات التعليق الصوتي بأزمنتها لتمكين التظليل أثناء التشغيل:

```ts
// types.ts:1897-1901
export type WordBoundary = {
  text: string;
  audioOffsetMs: number;
  durationMs: number;
};
```

التخزين والجلب:

- `audioWordformsReducer.ts:5-13` يخزّن خريطة `{ [assetId: number]: { state: 'loading'|'loaded'|'error', wordBoundaries?, error? } }` — أي أن الكلمات مفتاحها **assetId** لا معرّف المقطع.
- `sagas/audioWordformsSaga.ts:12-27` يستدعي `wordBoundaries(assetId)` من `AppServices/wordBoundaries` ويطلق `getWordBoundariesSuccess` أو `getWordBoundariesFailure`.
- الجانب السحابي: `VSCAssetAudioData.wordBoundaries` (`types.ts:604-611`) و`AudioClipMetaData.wordBoundaryData` (`types.ts:321`) و`AzureWordBoundary = {Text, AudioOffset, Duration}` (`types.ts:1891-1895`) — تحويل مباشر من مخرجات Azure Speech.

استيراد `.scribe` قديمًا يُجري تحويل الصوت إلى mp3 (عبر `mediabunny` في `sagas/legacyProjectMigration/audioConversion.ts`) ثم يرفعه كأصل ويبني `audioClips` وطبقاتها. نقطة مهمة للمنافس: **wordforms لم تُخزَّن في الملف القديم**، بل تُشتق سحابيًا للمقاطع المرفوعة — وهذا يعني أن البديل يجب أن يولّدها عند الرفع أو الاستيراد ليضمن المزامنة.

## 5. الصيغة: الحديثة (JSON) والقديمة (`.scribe`) ودورة `processScribeFile`

### 5.1 الصيغة الحديثة

المشروع الحديث مستند JSON يُرسل ويُستقبل عبر `project-data`:

- **الإنشاء**: `createProject` يرسل `{ title, appName: productName, projectModel }` إلى `POST {baseUrl}project-data` (`AppServices/projects.js:36-45`، حيث `appName` يُبنى من `productName` = `videoscribe-cloud`).
- **التحديث**: `updateProject` إلى `PUT {baseUrl}project-data/{id}` مع حذف حقول الخدمة قبل الإرسال: `delete clone.updatedOn; delete clone.viewOnly;` (`projects.js:69-74`).
- **القراءة**: `GET {baseUrl}project-data/{id}` يعيد `ScribeObject` (`projects.js:25-26`).
- عمليات أخرى: `POST project-data/duplicate/{id}` (`projects.js:89-90`)، و`POST project-data/from-template/{templateId}`، و`GET user/{uid}/projects/videoscribe-cloud` للقائمة.

الجدول التالي يجمع كل نقاط النهاية المرصودة في طبقة `AppServices`، وهي «صيغة الاتصال» الفعلية بين التطبيق ومخدمة Sparkol:

### 5.2 الشكل القديم (`.scribe`)

ملف الإصدارات القديمة أرشيف **ZIP** يحتوي XML. العناصر فيه تأتي بأنواع وسوم `drawing` و`gif` و`split_text` و`text`، بخصائص مسطّحة على شكل سلاسل نصية. أبرز الخصائص وترجمتها للموديل الحديث:

| خاصية قديمة | المعنى | الترجمة الحديثة |
|---|---|---|
| `elementID` | معرّف العنصر | `element.id` |
| `currentPosX/Y` | الموضع الحالي | `x`, `y` (بعد `fitProjectToCanvas`) |
| `scalesX/Y` + `theScale` | المقاييس | `scaleX`, `scaleY` |
| `renderAspect` | أبعاد المشهد | `canvasSize` عبر `resolveCanvasSize` |
| `drawStyle` | أسلوب الرسم | أنيميشن دخول + `drawType` |
| `movinCompass` | اتجاه الدخول | `direction` في الـ tween |
| `drawingXML` | بيانات الرسم/الصورة (base64) | أصل مرفوع + `image.assetId` |
| `drawingText` | نص العنصر | `text` |
| `transitionTime` / `pauseTime` / `targetTime` | أزمنة | `animationTime` / `pauseTime` |
| `cameraPositionX/Y` + `cameraScale` | كاميرا قديمة | `ScribeCameraElement` عبر `cameraFromLegacyAttrs` |

| `backingTrack` / `voiceOver` | موسيقى/تعليق | تحويل mp3 + `audioClips` |

### 5.3 خطوات `processScribeFile` بالتفصيل

الملف: `sagas/legacyProjectMigration/processScribeFile.ts`. الخطوات المرصودة بالترتيب:

1. **تحميل JSZip ديناميكيًا** (لتقليل حزمة الإقلاع): `loadJSZip()` تستورد `jszip` عند الحاجة فقط (`processScribeFile.ts:19-26`).
2. **فك الأرشيف** وقراءة الملفات الرئيسية: XML المشروع + أصول الصورة + الأصوات + `thumb.png` (إن وُجدت) + ملفات `.vsfont`.
3. **معالجة الخطوط القديمة**: كل `.vsfont` هو **ZIP داخل ZIP** يحتوي `font.xml`؛ يُقرأ `charCode` لكل حرف مع المقاييس (`loadVSFonts`, `processScribeFile.ts:109-160`). وقياس عرض النص يتم عبر `measureVSFontLineWidth` باستخدام تقدّم الحروف + `charSpace` + `spaceWidth` (`processScribeFile.ts:163-177`). وانحدار خط القاعدة الافتراضي `@lineHeight` تقريبًا 71 لخط Staatliches مع تعويض احتياطي عند غياب الخط (`processScribeFile.ts:83-85`).
4. **تحديد حجم الكانفس** من `renderAspect`: `>= 1.5 → landscape`، `>= 0.85 → square`، وإلا `portrait` (`processScribeFile.ts:188-191`)، ثم تحديد المرجع: `1920×1080` للأفقي و`1080×1920` للعمودي و`1080×1080` للمربع (`processScribeFile.ts:194-204`).
5. **الكاميرا**: `cameraFromLegacyAttrs` تقرأ `cameraPositionX/Y` و`cameraScale` وتعيد `{ x: -camPosX / camScale, y: -camPosY / camScale, scale }` (`processScribeFile.ts:206-220`) — لاحظ **السالب** لأنه تحويل من موضع الكاميرا إلى إزاحة العالم. ثم `cameraFitToBounds` لحساب كاميرا مناسبة لحدود العناصر (`processScribeFile.ts:225-243`).
6. **إعادة توسيط المشروع كله**: `fitProjectToCanvas` يحسب bounding box لكل العناصر ويعيد إزاحتها لتتوسط (`processScribeFile.ts:245-298`).
7. **الصور**: `drawingXML` (base64) → bytes → كشف SVG أو GIF، وأبعاد GIF تُقرأ يدويًا من ترويسة الملف (`readGifDimensions`, `processScribeFile.ts:57-64`) لأن الصيغة القديمة لا تخزّنها.
8. **النصوص**: وسوم `split_text`/`text` تتطلب قياسًا بالخط القديم لتوليد `charBounds` حديثة.
9. **الكاميرا النهائية**: `buildCameraElement(view, animationTime)` تبني عنصر كاميرا حديثًا (`processScribeFile.ts:300+`).
10. **الأصوات**: تحويل إلى mp3 ورفعها كأصول (`audioConversion.ts`)، ثم بناء `audioClips` و`audioLayers` و`projectAudioLayerIds`.
11. **التجميع**: بناء نموذج حديث ثم إنشاء مشروع جديد على السحابة، ويُضاف إلى المخزن عبر `setConversionComplete` (`reducers/legacyProjectMigration.ts` + `reducers/scribesReducer.ts:356-364`).

الدرس المعماري هنا أن Sparkol نقلت من **سنابشوت كامل مسطّح بأخطاء صيغ** إلى **مخطط كائني مرجعي (normalized)** — لكن أخطاء القياس النصي القديم بقيت مذكورة في تعليقات الكود كمرجع للتوافق البصري.

### 5.4 دورة تحميل المشروع إلى المحرر

دورة الافتتاح موزّعة على sagas قبل أن يستلمها الـreducers. المسار كما يلي:

1. **`prepProjectForEditor`** (`sagas/projectSagas/prepProjectForEditor.ts:85+`) — نقطة الدخول عند طلب فتح مشروع:
   - تفحص أولًا طابور الحفظ التلقائي للمشروع نفسه: إن كان عليه حفظ معلّق أو جارٍ، تنتظر انتهاءه مع مهلة قصوى 30 ثانية وتعرض للمستخدم رسالة "Waiting for previous changes to save" (`prepProjectForEditor.ts:107-120`)؛ وإن انتهت المهلة يظهر خطأ يطلب إعادة المحاولة. هذا حل عملي لمشكلة «فتح النسخة قبل حفظ تعديلاتها».
   - ثم تطلق `loadScribeById` وتنتظر النتيجة (`LOAD_SCRIBE_BY_ID_SUCCESS/FAILED`).
2. **`loadProjectById`** (`sagas/projectSagas/loadProjectById.ts:17-59`):
   - تستدعي `getProject(scribeId, appServices.exchangeCognitoTokenForSparkolToken)` — أي أن توكن Cognito يُبادَل بتوكن Sparkol قبل الطلب (`loadProjectById.ts:26-30`).
   - تصحّح علم `viewOnly` للحسابات المدفوعة: `scribeObject.viewOnly = false` لأن الـ API يحدّده بحسب الجلسة وقد لا تتجدد بعد الترقية فورًا (`loadProjectById.ts:33-40`).
   - تبني الموديل: `ScribeModel.fromObject(scribeObject)` (`loadProjectById.ts:42`).
   - تُحمّل خطوط المستخدم (`getUserFonts` ثم `loadUserFonts(scribe)`, `loadProjectById.ts:44-46`).
   - تُبلّغ بالنجاح `loadScribeByIdSuccess({ scribe })` مع تتبّع `trackOpenScribe`، وعند الفشل: `loadScribeByIdFailed` + إرسال لـSentry (`loadProjectById.ts:52-58`).
3. **معالجة ما بعد التحميل في `prepProjectForEditor`**: فحص خطوط المشروع (`checkScribeFonts`)، وتنظيف الموديل (`sanitiseScribe`، سطر 51)، وتحديث تغطية الكاميرا (`updateCameraCoverage`، سطر 50)، ثم **جلب أصول الصور** عبر مسار يعيد `{ assetId, blobUrl }` (`GetAssetUrlResult`، الأسطر 80-83): يُنفَّذ `processImageFileOnLoad` و`applyImageHeightAndWidth` وتُعالج الصور المكسورة بـ`appliesBrokenImage` (الأسطر 52-54)، وإن كان الأصل مفقودًا يُعاد رفعه عبر `uploadImageAssetOnLoad` (سطر 45).

الدرس: **فتح المشروع ليس قراءة JSON فقط، بل خط إنتاج**: انتظار حفظ → جلب → ترحيل → فحص خطوط → بناء blob URLs للصور → تحديث كاميرا. أي إعادة تنفيذ ينبغي أن تبني «عملية فتح» ذرّية (atomic) بهذه الخطوات، وإلا ورثت أخطاء التسابق (races) نفسها بين الحفظ والفتح.

## 6. الحفظ: المحلي مقابل السحابي ومعرّفات الأصول

### 6.1 لا يوجد «حفظ محلي» للمشروع

نتيجة الفحص: لا توجد أي آلية لحفظ بنية المشروع في ملف محلي أو في IndexedDB. ما وُجد:

بلوبات الأصول المخزنة تصبح blob URLs في الجلسة، وتُعلَّق على العنصر كحقول فورية `_imageUrl` تُمسح عند النقل (`sagas/sagaHelpers/sanitizeScribeForTransport.js:6-19`).

### 6.2 دورة الحفظ التلقائي

المسار الكامل: `UPDATE_SCRIBE` → تنظيف → طابور → polling → PUT:

```ts
// sagas/autoSaveSaga/autoSavePollingSaga.ts:10-28
export const AUTO_SAVE_INTERVAL = 2000;

export function getPendingSaveQueue(state: RootState, projectId: number): PendingSave {
  return state.autoSave.pendingSaveQueue[projectId];
}

export function* autoSavePollingSaga(
  projectId: number
): Generator<CallEffect | SelectEffect | PutEffect | Generator, void, PendingSave> {
  while (true) {
    yield delay(AUTO_SAVE_INTERVAL);
    const pendingSaveQueue = yield select(getPendingSaveQueue, projectId);

    if (pendingSaveQueue?.pendingSave) {
      const pendingProject = sanitizeScribeForTransport(pendingSaveQueue.pendingSave);
      yield put(pickPendingAutosave(projectId));
      yield saveProject(pendingProject);
    }
  }
}
```

والطابور بنية `{ [projectId]: { isSaving, pendingSave } }` (`types.ts:811-818`) مع `autoSaveStatus` و`autoSaveError` (`types.ts:820-824`). و`sanitizeScribeForTransport` يحذف:

- `_imageUrl`, `_imageLoaded`, `_imageLoading`
- `image.imgUrl`
- `audioClip.url` (وهي روابط موقّعة مؤقتة)
- واختياريًا `scribe.id` و`scribe.publicSharingId` حسب وسيطين (`sanitizeScribeForTransport.js:3, 21-31`)

### 6.3 الأصول والمعرّفات

- المعرّفات الحديثة **رقمية** (`assetId: number` في `ImageDetails` و`AudioClipData`).
- أثناء ترحيل `.scribe` تظهر معرّفات بشكل `file::<id>.svg` / `file::<id>.gif` قبل الرفع.
- الجلب دفعة واحدة: `GET project-assets?assetIds=...` يعيد روابط موقّعة (signed URLs)، ثم تُحمَّل وتخزّن محليًا.
- الرفع: `POST project-asset` (multipart باسم `assetFile`)، وتعديل ميتاداتا: `PATCH project-asset/{id}`، والأصوات: `GET project-asset?type=...` و`GET project-assets/paged`.
- الخطوط أصول أيضًا: `FontAttributes.assetId` (`types.ts:462`) — أي أن الخط المرفوع يُخزَّن كأصل ويُشار إليه من العنصر.

### 6.4 التصدير

لا يوجد تصدير محلي. التصدير الفيديو يتم سحابيًا:

`POST render` → `GET render/{id}/progress` → `GET render/{id}/download-url` → `DELETE render/{id}`
(ويُدار في `sagas/downloadSagas.js` و`reducers/downloadReducer.ts`). أي أن المنتج **لا يملك مسارًا لتصدير مشروع أو حتى عرض دون خدمة الخلفية** — وهذا أكبر خطر معماري يورثه لمن يقلّده.

## 8. ما يحتاجه المنافس + نقاط تحسين

### 8.1 الحد الأدنى الوظيفي الذي يجب بناؤه (مستخلصًا من هذا التحليل)

1. **مخطط مشروع مرجعي**: `project → scenes[elementIds] + elements{id→element}` مع فرض ثابت: أول عنصر في المشهد كاميرا.
2. **محرّك توقيت بثلاث درجات fallback**: العنصر ← المشهد ← المشروع، مع قواعد خاصة (كاميرا أولى = 0، كاميرا بلا خروج، الصوت يمدّ المشهد).
3. **طبقتا صوت** (نطق + موسيقى) بحد أقصى، مع `startTime/startOffset/instanceDuration` وحساب طول صوتي للمشهد.
4. **wordforms** مولّدة عند رفع/تسجيل الصوت، مربوطة بالأصل لا بالمقطع.
5. **ناقل API رفيع** مع تنظيف الحقول الفورية قبل الإرسال وطابور حفظ.
6. **مستورد `.scribe`** بقياسات vsfont التقريبية (خط الأساس 71، viewBox ~175).
7. **كاش أصول** بمفاتيح محتوى (لا أرقام سلسلة) مع إبطال تلقائي.

### 8.2 نقاط الضعف في التصميم الحالي التي يجب تجاوزها

| المشكلة في VideoScribe | الدليل | التحسين المقترح |
|---|---|---|
| لا صيغة مشروع قابلة للتصدير/الاستيراد محليًا | لا مسار حفظ محلي؛ التصدير سحابي فقط (`downloadSagas`)، الحفظ عبر `PUT project-data/{id}` | **صيغة مفتوحة**: حزمة `.vsp` = JSON + مجلد أصول (manifest + blobs)، قابلة للاستيراد بلا شبكة |
| غياب رقم صيغة صريح | لا `schemaVersion`؛ يُستدل على النسخة من الحقول المهجورة (`audio?`, `rawElements?`, `customPauseTime`, …) و`lastSavedVersion` يُملأ بعد الفتح (`ScribeModel.ts:334`) | **ترحيلات مرتبطة برقم `schemaVersion`** مع سجل ترقيات اختباري ثابت (golden files) |
| المعرّفات الرقمية (`assetId: number`) | `types.ts:295`, `types.ts:442` | **معرّفات محتوى** (ULID للكائنات، hash للبلوبات) لمنع التصادم ودعم الدمج بين النسخ |
| تحميل/حفظ بالوثيقة كاملة | `sanitizeScribeForTransport` يرسل المشروع كاملًا؛ لا `PATCH` جزئي؛ polling يحتوي «المشروع كله» في الذاكرة | **حفظ تفاضلي** (JSON Patch على مستوى العنصر/المشهد) و**تحميل جزئي** (عناصر مشهد واحد عند الطلب) |
| undo/redo بسنابشوتات كاملة | `cloneDeep` لكل تغيير (`scribesReducer.ts:216`) | **أوامر تفاضلية** + قيود ذاكرة + ضغط (`Immer patches`) |
| الكاميرا الأولى «سحرية» غير موصوفة في النوع | لا حقل `isInitial`؛ القاعدة في `ScribeModel.ts:206-211` | حقل صريح `cameraRole: 'opening' \| 'move'` مع تحقق (invariant) في المخطط |
| ازدواجية تمثيل الأنيميشن | `entranceTween` مقابل `entranceAnimation` + تعليق `consts.ts:185` | تمثيل واحد (configuration + curves) مع مولّد tweens عند التشغيل |
| تدرّج الخلفية ورثت حقولًا مهجورة | `types.ts:227-234` | ترحيل مرة واحدة وإزالة الحقول القديمة من المخطط نهائيًا |
| معالجة قديمة تكشف كل الملفات في الذاكرة | قراءة ZIP عبر JSZip مقابل الجبال (JSZip نفسه مضمّن في التطبيق) | بثّ (streaming) الأصول مباشرة إلى التخزين |

### 8.3 خطة تنفيذ مقترحة بسبع مراحل

بناءً على ما سبق، المسار العملي الأسرع لمنافس عربي:

1. **مخطط + محرّك توقيت**: عرّف `ProjectModel`/`Scene`/`Element` بصيغة مفتوحة، واكتب محرّك التوقيت كدالة نقية `(project) → timeline` قابلة للاختبار وحدها — لأن كل الواجهة (محرر، معاينة، تصدير) ستستهلكه.
2. **نموذج الكاميرا أولًا**: طبّق قاعدة «كاميرا أولى لكل مشهد» مع تغطية تلقائية للعناصر، لأن أي تعديل لاحق عليها يغيّر كل الأنيميشن المرئي.
3. **طبقة أصول مجرّدة**: واجهة `AssetStore` (جلب/رفع/كاش) مستقلة عن المزوّد، بمفاتيح محتوى، مع وضع محلي كامل بلا شبكة.
4. **حفظ محلي-أولًا (offline-first)**: تخزين المشروع والأصول محليًا (SQLite/IndexedDB)، ومزامنة عند الاتصال عبر JSON Patch تفاضلي بدل الوثيقة الكاملة.
5. **الصوت وwordforms**: استقبل/ولّد `WordBoundary` عند الرفع، واربطها بالأصل، وابن مزامنة التظليل عليها.
6. **مستورد `.scribe`**: انقله إلى وحدة `worker` منفصلة، وثبّت قياسات vsfont كحالات اختبار (golden) حتى لا تتغيّر النصوص المستوردة عبر الإصدارات.
7. **RTL منذ اليوم الأول**: `textDirection` + تشكيل عربي + عكس اتجاهات الحركة — إضافته لاحقًا أغلى بعشرة أضعاف من بنائه مبكرًا.

### 8.4 دعم RTL — الفجوة الأكبر لمنتج عربي

لا شيء في الموديل يعرف اتجاه اللغة:

- لا حقل `direction` على النص أو المشروع (فقط `align: 'left' | 'center' | 'right'` — `types.ts:466`).
- `charBounds` تُبنى من اليسار، فالنص العربي سيُقدَّم حرفًا حرفًا بترتيب معكوس بصريًا.
- أنيميشنات بعينها (move-in، drag-in، slide) تفترض «يسار→يمين»؛ يجب عكس `direction` عند اتجاه RTL أو توليد تويين معكوس.
- القوالب والصور المولّدة ستحتاج مرآة تلقائية للعناصر المشهدية.

الحد الأدنى المقترح: `textDirection` على العنصر (auto|rtl|ltr) + محرّك تشكيل عربي (bidi shaping) قبل توليد `charBounds`، + تكييف اتجاهات الحركة، + مرآة تخطيط الواجهة والقوالب.
