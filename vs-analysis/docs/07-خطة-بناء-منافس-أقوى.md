# 07 — خطة بناء منافس أقوى (AI-First Whiteboard Studio)

> **الخلاصة:** VideoScribe منتج ناضج محرّكه جيد لكن نموذج عمله قديم (اشتراكات + قيود + سحابة + تتبّع). الفرصة ليست في تقليد واجهته، بل في **قلب خط الإنتاج**: أن يبدأ الفيديو من *نص* لا من *لوحة، وأن تُبنى الأصول والبصريات بالكود لا بالإنسان، وأن يكون كل شيء محليًا ومجانيًا وبلا حساب.
>
> هذا المستند مكتوب بعد تفكيك فعلي للنسخة 1.21.0 (وثائق 00–06) + قراءة خطة المستخدم ورؤيته + حالة مشروع `studio` الحالي.

| # | التقنية | التفصيل المرجعي | استخدامنا |
|---|---|---|---|
| 1 | نموذج الزمن **رباعي المراحل** | عنصر = دخول + تركيز (بحلقات) + خروج + وقفة؛ المشهد = `max(مدة الصوت، مجموع العناصر + زمن الانتقال)` | نموذجنا الأساسي (مع تفصيل أدق للوقفات) |
| 2 | **كشف الرسم بقناع متنامٍ** | قناع يُبنى حسب الطول المتراكم 0→1؛ المسح = نفس القناع معكوسًا | سنستخدم القصّ بالـ dash/المسار في Cairo (أدق وأسرع من الأقنعة النقطية) |
| 3 | **الحدود أولًا ثم الألوان** | نسبة `0.7` لحدود الرسم قبل بدء التعبئة | قاعدة أساس لدينا: «ارسم بالخط ثم لوّن» |

## 3. المكدّس التقني: قرار البناء

### الوضع الحالي لمشروعك `studio`
Python + PIL + ffmpeg + Qwen3 0.6B محلي + مكتبة 2159 SVG (Lucide) + 10 رسومات قصصية + يد مرسومة، محرك «خرائط الخطوط» (`stroke_map`) وتجميع مشاهد وكاميرا بين 4 مجموعات.

### الخيارات

| الخيار | الوصف | المزايا | العيوب |
|---|---|---|---|
| **أ) بايثون + Cairo/Pango (موصى به)** | نفس المحرك يعمل في الخلفية المحلية وفي التصدير: مسارات حقيقية، قصّ وdash، نص بتشكيل HarfBuzz | محرك واحد (لا تشتّت)، تشكيل عربي حقيقي مجانًا، دقة متجهية، سرعة عالية، متوافق مع مشروعك الحالي | معاينة تفاعلية أقرب «لمقاطع» (يمكن حلها بـ preview جزئي سريع) |
| ب) TypeScript + Canvas/WebGL | محرك ويب يعمل في المتصفح وفي التصدير بـ WebCodecs | تفاعلية 60fps فورية | إعادة كتابة كل شيء + تشكيل عربي عبر WASM + ثنائية اللغة في الفريق |
| ج) استمرار PIL | كما هو الآن | لا تغيير | جودة رسم ضعيفة، لا مسارات متجهية، نص عربي مرسوم يدويًا |

### التوصية: (أ) بايثون + Cairo/Pango — بمكوّنات محدّدة

```
[واجهة ويب محلية RTL]  ← (مشروعك الحالي، يُعاد تصميمها)
        │  JSON مفتوح للمشروع (Scenes/Elements/Timing/Audio)
[محرك المشروع]  scene_model.py (تحقق + حلّ الزمن + دمج الصوت)
        │
        ├── render_cairo.py     (Vector renderer) ─→ إطارات/مقاطع
        ├── stroke_engine.py    (تخطيط المسار + الفرش + التقدّم)
        ├── text_engine.py      (HarfBuzz + مسارات حروف + كشيدة)
        ├── hand_engine.py      (أيادي متعددة الإطارات + فيزياء)
        ├── audio_sync.py       (Whisper timestamps → خطة مناطق)
        └── export_ffmpeg.py    (H.264/AV1/VP9-alpha + SRT + مقاطع)
        │
[طبقة الذكاء الاصطناعي المحلية]
        ├── llm_planner (llama.cpp + Qwen3-4B/8B Q4، مخرجات JSON مقيّدة بقواعد)
        ├── image_gen (ComfyUI/SDXL + LoRA خطوط + ControlNet)
        ├── vectorizer (VTracer/potrace + ترتيب مسارات + وسوم ألوان)
        └── tts_ar (Piper/XTTS محلي، أو edge-tts كخيار شبكي)
```

> **قاعدة ذهبية:** الـ JSON المفتوح هو **العقد** بين الواجهة والمحرك والذكاء الاصطناعي. أي واجهة مستقبلية (ويب/سطح مكتب/جوال) تقرأ نفس الملف، وأي محرك آخر يمكن أن يستبدل `render_cairo` بلا تغيير بقية النظام. وهنا نتفوق على VideoScribe الذي يخلط الحالة الزمنية بـ GSAP ticker (وثيقة `03 §2.2`).

## 4. المحرك: تفاصيل تنفيذية (بأرقام)

### 4.1 نموذج الزمن
```jsonc
// project.json
{
  "version": 1,
  "canvas": { "w": 1920, "h": 1080, "fps": 60, "paper": "#fdfaf3" },
  "scenes": [{
    "id": "s1", "start": null,              // محسوب
    "audio": [{"src":"vo1.wav","start":0.0,"fade":[0.15,0.2]}],
    "camera": {"views": [{"at":0.0,"region":[0,0,1920,1080],"zoom":1.0},
                         {"at":3.2,"region":[1200,300,640,360],"zoom":1.6}],
               "ease":"power2.out"},
    "elements": [{
      "id":"e1", "type":"svg", "src":"assets/house.svg",
      "box":[240,180,640,420], "rotation":0,
      "entrance": {"kind":"draw","style":"marker","duration":3.4,"order":"auto"},
      "emphasis": {"kind":"pulse","times":2,"duration":1.2},
      "exit":     {"kind":"erase","duration":1.0},
      "pause": 0.4,
      "regions":  [{"word":"بيت","at":3.4}]   // خطة المناطق (Wordform)
    }],
    "transition": {"kind":"move-left","duration":0.8}
  }]
}
```
قواعدنا في حلّ الزمن (مستخلصة من تفكيك منافسنا ومحسّنة):
- مدة العنصر = `entrance + emphasis×times + exit + pause`، والتزامن مع الكلام يتقدّم على الحساب التلقائي.
- مدة المشهد = `max(نهاية الصوت، نهاية العناصر + الانتقال)`.
- دقة الحدود 0.05 ثانية (بدل 0.1 عند منافسنا) + محاذاة مغناطيسية للكلمات.

### 4.2 محرك الضربة (Stroke Engine)
1. كل شكل يُستورد إلى **مسارات Bézier** (من SVG أو من التوجيه الآلي).
2. تقسيم المسار إلى **مقاطع خطوط بحسب انحناء** (لتفادي تسريع/تباطؤ غير طبيعي).
3. الكشف بالتدريج: `stroke_dashoffset` (Cairo: `set_dash` + offset) — بديل أدق من أقنعة البكسل.
4. **سماكة متغيرة**: استخراج medial axis (skeleton + distance transform) ⇒ عرض القلم = `clamp(2·d · k، w_min، w_max)`.
5. **ترتيب الرسم**: 
   - أولًا الحدود (`#vs-outline`) بنسبة 70% من الزمن، ثم التعبئات.
   - ترتيب المسارات بـ greedy (أقرب نقطة بداية + أقل تغيّر اتجاه) ثم 2-opt.
   - دمج «رفع القلم» في الزمن (زمن انتقال قصير 60–120ms عند القفز بين مسارات متباعدة).
6. **نموذج سرعة إنساني**: السرعة تتناسب مع `1/(1+κ)` حيث κ الانحناء، مع تباطؤ عند نهايات المقاطع.
7. **الأنماط**: marker / pencil / chalk / ink / brush / highlighter (نقوش فرشاة PNG مع Alpha) + سماكة ديناميكية.
8. **الألوان**: تكميم Oklch (16–24 لونًا) + إعادة التلوين بالوسوم + فرض لوحة ألوان القالب (3 ألوان + أسود) لثبات الأسلوب.

### 4.3 المؤشر (اليد)
- مكتبة أيادي: (١) قلم ماركر، (٢) يد حقيقية، (٣) يد أيسر، (٤) ألوان بشرة متعددة، (٥) ممحاة، (٦) كفّ سحب، (٧) مسطرة/فرجار كعناصر إضافية، (٨) رفع يد مخصّص من المستخدم.
- لكل أصل: نقطة ارتكاز (tip offset) + مقياس + **3–8 إطارات** (لا إطاران فقط) + إيقاع تحديث الإطار بحسب السرعة.
- الطبقة: دائماً في أعلى المشهد، وتُخفى عند أخذ اللقطات الثابتة أو التصدير الخالي من اليد.
- فرصة التفوق: **يد مرسومة بالخطوط لا صورة فوتوغرافية** (تنسجم مع أسلوب الوايت بورد) + نسخة «قلم عربي/قصبة».

### 4.4 النص العربي (سلاحنا الحاسم)
- التخطيط: **HarfBuzz** (نفس محرك Chrome/Firefox) عبر `uharfbuzz` أو PangoCairo: تشكيل، اتصال، كشيدة، تشكيل حركات، أرقام عربية/هندية.
- الرسم: **مسارات الحروف الحقيقية من ملف الخط** ⇒ الرسم حرفًا-حرفًا مثل الكتابة اليدوية بجودة طباعة.
- السطور: كسر السطور حسب المقاس (لا حسب عدد أحرف) + محاذاة RTL/LTR تلقائية + خلط عربي/إنجليزي صحيح (BiDi كامل).
- الخطوط: حزمة عربية مدمجة (Noto Naskh/Kufi/Cairo/Amiri/Almarai) + خطوط المستخدم (TTF/OTF/WOFF2) + استيراد Google Fonts بلا إنترنت؟ (تُحمَّل وقت الاتصال وتُخزَّن).
- عند فقد خط: **تدرّج آمن** (خط بديل مطابق في المقاس والمحاذاة) لا «رجوع للافتراضي».
- TTS: Piper (سريع، محلي، أصوات عربية) / XTTS-v2 (استنساخ صوت) + edge-tts كخيار جودة.
- المزامنة: `faster-whisper` → حدود كلمات → خطة مناطق: كل عنصر يُرسم عند الكلمة المرتبطة به (هذا هو «Wordform» عند منافسنا، وثيقة `05 §2.2`).

### 4.5 الكاميرا والقالب البصري
- كاميرا **مقودة بالتخطيط**: المحرك يعرف مناطق الاهتمام من قوالب التخطيط (عنوان/صف عناصر/مقارنة/خط زمني/رسم بياني) ⇒ يقترح حركة كاميرا تلقائيًا، مع إمكانية التعطيل اليدوي.
- أبعاد: 16:9 / 9:16 / 1:1 / 4:5، وحلّ إعادة التوزيع تلقائيًا عند تغيير النسبة.
- ورق وخلفيات: أبيض/كريمي/شبكة/نقاط + إطارات.

## 5. طبقة الذكاء الاصطناعي (الميزة التي تجعلنا «خارقين»)

**الهدف:** أن يكتب المستخدم سطرًا واحدًا ويخرج فيديو كامل متزامن مع الصوت، ثم يعدّل بالتفصيل.

| المرحلة | التنفيذ | الموديل/الأداة | ملاحظة تفوق |
|---|---|---|---|
| 1. تحليل النص | تقسيم لمشاهد (25–35 ث)، استخراج الكيانات والمفاهيم | Qwen3-4B/8B عبر llama.cpp بـ GBNF (JSON مضمون) | لا «هلوسة»: كل مخرج يُتحقق منه بـ JSON Schema |
| 2. كتابة قائمة العناصر | لكل مشهد: 5–8 عناصر + قالب تخطيط + ربط كل عنصر بجملة | نفس الموديل + قوالب التخطيط | ربط «عنصر ↔ جملة» = تزامن مثالي |
| 3. توليد العناصر | صور خطية بستايل واحد (3 ألوان + أسود، مساحة فاصلة) | ComfyUI + SDXL/Flux + LoRA خطوط + ControlNet lineart | نولّد 3–5 نسخ ونختار آليًا (تشابه CLIP + تقييم خطوط) |
| 4. التوجيه (Vectorization) | صورة → SVG بمسارات مرتّبة + وسوم ألوان | VTracer/potrace + OpenCV + ترتيب مساراتنا | نرسم «بالحق» لا بقناع بكسل |
| 5. البحث الدلالي | بحث عربي عن أيقونة/رسم بمكتبتنا (2159 SVG) | CLIP/OpenCLIP عربي-إنجليزي + فهرس محلي | «سيارة» تجد «car» و«سيارة» و«مركبة» |
| 6. التعليق الصوتي | صوت عربي + توقيت كلمات | Piper/XTTS + faster-whisper | منافسنا يستخدم Azure Neural بـ**5 لهجات عربية** (إماراتي/مصري/عراقي/مغربي/سعودي) مع ملفات word-boundary — نطابقه محليًا ونضيف لهجات إضافية واستنساخ صوت |
| 7. الموسيقى/المؤثرات | اختيار موسيقى محايدة + مؤثرات كتابة | مكتبة محلية مجانية | بلا قيود حقوق |
| 8. المراجعة الذكية | كشف: عنصر بلا جملة، مشهد مزدحم، صوت أطول من الرسم | قواعد + موديل صغير | «مخرج آلي» يرفع الجودة |

**حدود عملية:** توليد الصور هو الجزء الوحيد الذي يحتاج GPU. الحل: (أ) GPU محلي، (ب) تشغيل على Kaggle/Colab ثم استيراد الحزمة، (ج) صور مرسومة بالكود من مكتبة SVG (قالب جاهز بلا GPU) — وهذا الأخير يعطي **تجربة كاملة بلا كارت شاشة**، وهي ميزة لا يقدّمها أحد.

## 11. الخطوة العملية التالية (أسبوع واحد)

1. **تجربة قياس**: أعد رسم مشهدك «يوسف» الحالي بمحرّك Cairo/Pango + stroke engine جديد وقارن الإطارات — الهدف: فرق جودة يُرى بالعين في نفس الوقت.
2. **تثبيت العقد**: اكتب `scene_schema.json` (JSON Schema) وولّد منه نسخة Python (pydantic) ونسخة JS — أي مخرج AI يُتحقق منه.
3. **خط الأنابيب**: `text → llm_planner → scene JSON → render → mp4` في أمر واحد، وبلا أي مكوّن سحابي.
4. **حزمة الأصول**: ابدأ بـ 60 عنصرًا موسومًا عربيًا عالي الجودة (بيت، سيارة، عائلة، مال، كتاب، ساعة، خريطة…) لتغطية 80% من المواضيع قبل التوسّع الآلي.
